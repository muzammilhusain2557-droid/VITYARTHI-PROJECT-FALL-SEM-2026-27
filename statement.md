Project Statement
Project Title
Doctor - Patient Health Assistant
1. Problem Statement
Managing basic patient information across different health-related records can become difficult when information such as medical history, medicines, doctor visits, and vital signs is recorded separately.
The Doctor - Patient Health Assistant addresses this problem by providing a simple command-line application where basic patient information and health records can be entered, organized, and viewed through a single menu-driven system.
The project focuses on creating a simple and understandable solution using Python programming concepts covered in the course.
2. Scope of the Project
The scope of the current project includes basic organization of a single patient's health information during a program session.
The application covers:
Patient basic information
Medical history
Medicine records
Doctor visit records
Vital-sign records
Patient summary
The current version is a command-line application and stores information only while the program is running. Permanent database or file storage is outside the current implementation.
3. Target Users
The intended users of this educational application are:
Students learning Python programming
Beginners developing menu-driven applications
Users who want to demonstrate basic organization of health-related records
Academic evaluators reviewing a Python project
The application is not intended to replace professional medical software or healthcare services.
4. High-Level Features
Patient Setup
The program collects the patient's:
Name
Age
Gender
Previous medical conditions
Medical History
Users can add and view:
Previous illness or condition
Year or period
Additional details
Medicine Tracker
Users can record:
Medicine name
Dosage
Timing
Doctor Visits
Users can record:
Doctor name
Visit date
Reason for visit
Doctor's notes
Vital Signs
Users can record:
Date
Temperature
Heart rate
Systolic blood pressure
Diastolic blood pressure
Patient Summary
The system provides a summary containing the patient's basic information, medical history, and counts of medicines, doctor visits, and vital records.
5. User Workflow
Start Program
      ↓
Enter Patient Information
      ↓
Enter Previous Medical History
      ↓
Display Main Menu
      ↓
Choose a Module
      ↓
Add or View Records
      ↓
Return to Main Menu
      ↓
Exit Program
6. Technical Approach
The project is implemented using Python and uses:
Functions for modular program organization
Lists for storing multiple records
Dictionaries for organizing individual records
Loops for repeated menu interaction
Conditional statements for menu selection
Input validation for user-entered data
try-except for handling invalid numeric input
7. Current Limitations
The current implementation has some limitations:
Data is not permanently stored.
The program currently focuses on one patient session.
There is no database.
There is no graphical user interface.
There is no user authentication.
The current application is intended for educational use rather than clinical use.
8. Future Scope
The application can be expanded by adding:
Database integration
Permanent record storage
Multiple patient accounts
Search, edit, and delete operations
Authentication and access control
Report generation
Graphical user interface
Automated testing
More advanced health-record features
9. Project Purpose
The primary purpose of this project is to apply Python programming concepts to a meaningful real-world problem while demonstrating structured problem solving, modular implementation, input validation, and basic data management.
